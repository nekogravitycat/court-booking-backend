# 2026-11-16 Frontend Changelog

新增「教練與課程」整套 API：教練身分與審核、教練團、課程與報名、轉帳核帳、取消與退款紀錄、請假補課出席、評價、申訴、信譽與停權。完整欄位請看 OpenAPI（`docs/openapi.yml`，新增的 tag：Coaches、Coach Groups、Courses、Enrollments、Payments、Cancellations、Attendance、Reviews、Complaints、Reputation、Suspensions）。

## 與原需求文件不同的地方

| 原需求 | 實作 | 原因 |
| --- | --- | --- |
| 轉帳由管理員核帳 `/admin/transfer-reports` | **開課教練**審核：`GET /transfer-reports`、`POST /transfer-reports/{id}/review` | 收款方是教練。系統管理員看得到全部，也能審核 (監督用) |
| 取消申請由管理員處理 `/admin/cancellation-requests` | **開課教練**處理：`GET /cancellation-requests`、`POST /cancellation-requests/{id}/resolve` | 同上，退款在教練手上 |
| 邀請成員 `POST /coach-groups/{id}/members` 直接加入 | 邀請 → 被邀請者同意：`POST /coach-groups/{id}/invitations`、`POST /coach-invitations/{id}/accept\|decline` | 需被邀請者同意 |
| 成員狀態「活動中、活修中」 | `active` / `inactive` | 暫定值 |
| `POST /enrollments/{id}/review` | 不變，另需出席過至少一堂 | |

## 重點行為

- **報名與付款狀態分開**：`enrollment.status`（`active` / `cancelled`）與 `payment_status`（`not_required` / `unpaid` / `reported` / `paid` / `refunded`）。**未經教練核帳的轉帳不會變成 `paid`**，回報後是 `reported`。
- **轉帳金額** = 課程費 + 場地費（`total_fee` / `amount_due`）。報名時金額是快照，之後課程調價不影響已報名的人。
- **課程規則**：結構化欄位（`allow_leave`、`leave_deadline_hours`、`allow_makeup`、`makeup_limit`、`makeup_valid_days`、`allow_cancel`、`cancel_deadline_hours`）由系統檢查；文字規則（`rules_leave` / `rules_makeup` / `rules_cancellation` / `rules_refund` / `rules_noshow`，各 500 字）只顯示給學員看。
- **不自動計算也不執行退款**：只記錄教練的決定（`resolution`: `cancelled` / `refunded` / `makeup` / `rejected` / `other`，退款金額）。唯一的自動化：課程允許取消、尚未涉及金錢、未過期限時，學員的取消會立即生效。
- **開課與場地預約分開**：課程只有 `venue_name`（自由文字）與選填的 `location_id`，不會預約場地。
- **匿名名單**：課程詳情的 `participant_stats`（性別、年齡層、程度人數，格式同臨打團的 participant-stats）；完整名單 `GET /courses/{id}/enrollments` 只有開課者能看。
- **轉帳資訊**（`bank_*`）只給課程管理者與已報名的學員；公開頁只有 `bank_info_available`。
- **證照檔案**：上傳用既有 `POST /files`，再把 `file_id` 放進申請；檔案僅登入者可讀（原本行為）。證照／照片必須是本人上傳的檔案。
- **週期課**：建立時傳 `schedule`（每週模式）或 `sessions`（明確清單）擇一，後端展開成場次（上限 100 堂）。`weekdays` 為 0=週日…6=週六，時間是課程時區的牆上時間。
- **補課**：選項是同一開課者（教練或教練團）、同球類的**其他班級**的未來場次，且有名額。選定時後端會再檢查一次資格、期限與名額。
- **停權**：不會自動取消任何東西；回應的 `impact` 列出受影響的課程、場次、報名供管理員處理。停權教練從公開目錄消失，也不能接受新報名。
- **信譽**：內部帳本，沒有自動扣分或停權規則（起始分 100 只是暫定顯示值）。公開評價（`rating.average`、`/coaches/{id}/reviews`）與內部分數分開。

## 流程速覽

```
教練：POST /coach-applications → (管理員) POST /admin/coach-applications/{id}/review → approved
      → POST /coach-groups (可選) → POST /courses

學員：GET /courses → POST /courses/{id}/enrollments {payment_method}
      轉帳：POST /enrollments/{id}/transfer-reports {last5}
            → (教練) POST /transfer-reports/{id}/review {approve|reject}   → payment_status: paid / unpaid
      現場：(教練) PATCH /enrollments/{id}/payment {paid}
      請假：POST /sessions/{id}/leave-requests → GET /leave-requests/{id}/makeup-options
            → POST /leave-requests/{id}/makeup-selection
      出席：(教練) PATCH /sessions/{id}/attendance
      評價：POST /enrollments/{id}/review    申訴：POST /complaints
```

## 通知

沿用既有收件匣（`/notifications`），新增欄位 `ref_type` / `ref_id` 指向相關實體（`coach`、`coach_group`、`coach_group_invitation`、`course`、`enrollment`、`course_session`、`transfer_report`、`cancellation_request`、`leave_request`、`coach_review`、`complaint`、`coach_suspension`）。新增的 `type`：

`coach_application_submitted/approved/rejected`、`coach_group_invited/invite_accepted/invite_declined/member_changed/member_removed/member_left/disbanded`、`course_enrolled/session_changed/session_cancelled/cancelled/updated`、`transfer_reported/approved/rejected`、`payment_updated`、`cancellation_requested/resolved`、`enrollment_cancelled`、`leave_requested`、`makeup_booked/released`、`coach_review_received`、`complaint_filed/updated`、`coach_suspended`、`coach_suspension_lifted`。

## 已知限制 / 之後再說

- 評價送出後不能修改（管理員可隱藏）。評論為選填，最多 50 字。
- 沒有候補名單。
- 教練帳號被停用時，其課程會從公開搜尋消失，但既有報名不會被自動取消。
- 補課只能補到「同一開課者的其他班級」；同班的其他場次視為正式課程。
- 課程取消後，已付款 / 已回報的報名會自動建立一筆待處理的取消申請，當作教練的退款待辦清單。
