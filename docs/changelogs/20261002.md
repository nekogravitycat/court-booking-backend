# 2026-10-02 Frontend Changelog

## 預約與資源新增 `sport_id`

資源（resource）現在可以關聯一個運動項目，預約（booking）會透過其資源帶出 `sport_id`。此欄位對應 sports 的 `id`（UUID），為**可為 `null`** 的欄位，既有資源與預約在設定前皆為 `null`，前端需處理 `null` 的情況。

### Response 新增欄位

以下 response 新增 `sport_id`：

- 預約（`GET /bookings`、`GET /bookings/{id}` 及其他回傳預約的 API）：頂層新增 `sport_id`。
- 資源（`GET /resources`、`GET /resources/{id}` 及其他回傳資源的 API）：新增 `sport_id`。

```json
{
  "id": "預約 UUID",
  "resource": { "id": "資源 UUID", "name": "A 場" },
  "sport_id": "運動 UUID 或 null"
}
```

`sport_id` 是 `resource_type` 之外獨立的欄位，兩者不會互相連動。

### 建立與修改資源

`POST /resources` 與 `PATCH /resources/{id}` 新增選填欄位 `sport_id`：

```json
{
  "sport_id": "運動 UUID"
}
```

- 必須為 UUID 格式且對應存在的運動項目，否則回傳 `400`（`invalid sport_id`）。
- `POST` 省略時為 `null`。
- `PATCH` 時：
  - `"sport_id": ""`：清除，回到 `null`。
  - 省略 `sport_id`：保持原值。
  - `"sport_id": null`：保持原值。

## 預約規則調整

- 時間必須對齊 30 分鐘（以場地時區的牆上時間計算），否則 `400`（`booking start and end must fall on a 30-minute boundary`）。
- `start_time` 最遠為現在起 90 天，否則 `400`。
- 每位使用者「尚未結束且未取消」的預約最多 10 筆，超過回 `409`。
- 預約本人（非管理者）的限制（比照臨打訂單）：
  - 已確認、申請取消中、或已付款的預約：不能直接 `cancelled` 或 `DELETE`（`403`），只能 `cancel_request`，由管理者核准。
  - 只有「待確認、未付款、尚未開始」的預約才能自行改期，否則 `403`。
  - 已取消的預約不能由本人改回佔位狀態（`403`）。
- `PATCH /bookings/{id}` 若在讀取後被他人同時修改，回 `409`（`booking was modified by someone else; reload and retry`），請重新讀取後再試。
- 預約回傳的使用者名稱在 `display_name` 為空時回退為 `username`。

## 臨打

- 被團主 `rejected` 的報名者，無法再自行把訂單改成 `cancelled` / `cancel_request` / `pending`（`403`），也就無法重新報名。已 `cancelled` 的訂單同理，要重新報名請呼叫 `POST /pickup-groups/{id}/orders`。
- `GET /pickup-groups/{id}` 的 `host.phone` 只回傳給團主、System Admin、以及訂單狀態為 `confirmed`（或 `cancel_request`）的參與者；其他人為 `null`。
- `GET /hosts/{host_id}/pickup-groups` 對團主本人與 System Admin 以外的請求（含未登入）不再回傳 `enable=false` 的團。
- 單人報名時，若使用者沒有 `display_name`，訂單與通知中的報名者名稱改用 `username`（原為 email）。
- 團不存在的 `location_id` 現在回 `404`（`location not found`），不再是 500。

## 帳號

- `display_name` 為空白（只含空白字元）時，註冊與 `PATCH` 皆回 `400`（`display_name must not be blank`）。
- `phone` 可傳空字串清除。
- 停用（`PATCH is_active=false`）或刪除帳號時，會自動：取消該使用者未來的預約、取消其尚未結束的臨打報名（通知團主）、取消其開的進行中臨打團（通知已報名者）。
- 不能停用 / 刪除自己（`403`），也不能停用最後一位啟用中的 System Admin（`409`）。
- 建立組織或轉移擁有者時，新擁有者必須是啟用中的帳號，否則 `400`。

## 其他

- 場地建立時，`longitude` / `latitude` 可為 `0`；缺少時仍回 `400`。
- 場地 `PATCH` 的 `name` 只含空白會回 `400`；資源 `name` 會自動去除頭尾空白。
- 指派非組織成員為場地管理員回 `400`（原為 500）；`GET /files/{id}` 找不到或 ID 格式不合法回 `404`（原為 500）。
- 列表的 `name` / `email` / `display_name` / `keyword` 搜尋會把 `%`、`_` 視為一般字元。
- 所有列表加上穩定的次要排序鍵（`id`），分頁不再因排序值相同而重複或遺漏。
