# 2026-10-02 Frontend Changelog

## 預約與資源新增 `sport_id`

資源（resource）現在可以關聯一個運動項目，預約（booking）會透過其資源帶出 `sport_id`。此欄位對應 sports 的 `id`（UUID），為**可為 `null`** 的欄位，既有資源與預約在設定前皆為 `null`，前端需處理 `null` 的情況。

### Response 新增欄位

以下 response 新增 `sport_id`：

- 預約（`GET /bookings`、`GET /bookings/{id}` 及其他回傳預約的 API）：頂層新增 `sport_id`。
- 資源（`GET /resources`、`GET /resources/{id}` 及其他回傳資源的 API）：新增 `sport_id`。

```json
{
  "id": "預約 UUID",
  "resource": { "id": "資源 UUID", "name": "A 場" },
  "sport_id": "運動 UUID 或 null"
}
```

`sport_id` 是 `resource_type` 之外獨立的欄位，兩者不會互相連動。

### 建立與修改資源

`POST /resources` 與 `PATCH /resources/{id}` 新增選填欄位 `sport_id`：

```json
{
  "sport_id": "運動 UUID"
}
```

- 必須為 UUID 格式且對應存在的運動項目，否則回傳 `400`（`invalid sport_id`）。
- `POST` 省略時為 `null`。
- `PATCH` 時：
  - `"sport_id": ""`：清除，回到 `null`。
  - 省略 `sport_id`：保持原值。
  - `"sport_id": null`：保持原值。
