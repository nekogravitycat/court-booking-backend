## 1. 臨打團清單篩選 / 排序

`GET /pickup-groups`、`GET /hosts/{host_id}/pickup-groups` 新增參數：

| 參數 | 說明 |
|------|------|
| `skill_level` | 精確篩選程度（整數） |
| `fee_min` / `fee_max` | 價位區間（含）；`fee_min > fee_max` → `400` |
| `followed_only=true` | 只顯示**我追蹤的教練**（沿用 `/favorites/host`）。**需登入**，未帶 token → `401` |
| `latitude` + `longitude` | 使用者座標，須**同時提供**；提供後每筆回傳 `distance_km`（公里，球面距離） |
| `sort_by` | `start_time`（預設）/ `created_at` / `skill_level` / **`distance`**（必須帶座標，否則 `400`） |
| `sort_order` | `asc` / `desc`。預設：`distance` 為 `asc`（最近優先），其餘 `desc` |

- `PickupGroupBrief` 新增 `distance_km`（未帶座標為 `null`）。
- 分頁 `total` 已反映篩選結果。

## 2. 程度改為整數 — Breaking

現在有關程度的表示**一律用整數**（方便取平均）。文字標示由各球類自己的對照表提供，因此不同球類可以有不同的量表最高值與定義。

**`/skill-levels`（對照表）**

| 舊 | 新 |
|----|----|
| `name` | `label` |
| `sort_order` | 移除 → 改用 `level`（整數，同球類內唯一，建立後不可改） |
| `id` | 仍保留（CRUD 用） |

- 建立：`{ sport_id, level, label }`；同球類 `level` 或 `label` 重複 → `409`；允許跳號。
- 更新：只能改 `label`、`is_active`。
- 既有資料遷移：各球類依舊 `sort_order` 重新編號為 `1..n`（例：原 A/B/C/D → `1/2/3/4`，標籤沿用 `A/B/C/D`）。

**臨打團**

| 舊 | 新 |
|----|----|
| 建立/更新 body：`skill_level_id`（uuid） | **`skill_level`（整數）** |
| 篩選：`?skill_level_id=` | **`?skill_level=`（整數）** |
| 回應 `skill_level: { id, name }` | **`skill_level: { level, label }`**（`label` 取自該球類對照表） |

驗證：`skill_level` 須是該球類對照表**已定義且啟用**的程度，否則 `400`。

## 3. 單人報名必填自填程度 — Breaking

`POST /pickup-groups/{id}/orders` 原本沒有 body，現在必須帶：

```json
{ "skill_level": 2 }
```

- 未帶或程度未定義 → `400`。
- 訂單回應新增 `skill_level`、`party_size`（單人為 `1`）。
- 此程度為**報名者自填**，用於「已報名者統計」；與第 8 節的主辦人評分無關。

## 4. 使用者性別與生日

- `UserResponse` 新增 `gender`（`male` / `female` / `other`）、`birth_date`（`YYYY-MM-DD`）、`age`（由生日推算的足歲）；皆可為 `null`。
- 註冊 `POST /auth/register` 可選填 `gender`、`birth_date`。
- **新增 `PATCH /me`**：使用者修改自己的 `display_name`、`phone`、`gender`、`birth_date`（原本只有系統管理員能改資料）。不能改 `is_active` / `is_system_admin`。
- `birth_date` 不可為未來日期、不早於 `1900-01-01`；格式錯誤或 `gender` 不合法 → `400`。
- 管理員的 `PATCH /users/{id}` 也可改 `phone`、`gender`、`birth_date`。

## 5. 已報名者匿名統計 — `GET /pickup-groups/{id}/participant-stats`（公開）

統計範圍：訂單狀態 `pending` + `confirmed` 的座位（多人報名每人一個座位）。只回傳人數，**不含任何身分資訊**。

```json
{
  "total": 5,
  "genders":    [{ "gender": "male", "count": 1 }, { "gender": "female", "count": 2 }, { "gender": "other", "count": 1 }, { "gender": "unknown", "count": 1 }],
  "age_groups": [{ "age_group": "under_18", "count": 0 }, { "age_group": "18_24", "count": 0 }, { "age_group": "25_34", "count": 1 }, { "age_group": "35_44", "count": 0 }, { "age_group": "45_54", "count": 0 }, { "age_group": "55_plus", "count": 0 }, { "age_group": "unknown", "count": 4 }],
  "skill_levels": [{ "level": 1, "label": "A", "count": 2 }, { "level": 2, "label": "B", "count": 3 }, { "level": 3, "label": "C", "count": 0 }, { "level": 4, "label": "D", "count": 0 }]
}
```

- `genders` / `age_groups` 固定回傳全部項目與順序（人數可為 0）；沒填性別/生日的計入 `unknown`。
- 多人報名的同行成員沒有年齡，一律計入 `age_group: "unknown"`。
- `skill_levels` 列出該球類對照表的所有程度（人數可為 0），由低到高。
- 年齡以場地所在時區的今天計算。

## 6. 多人報名 — `POST /pickup-groups/{id}/party-orders`

```json
{
  "organizer_name": "小明",
  "party_size": 3,
  "members": [
    { "gender": "male",   "skill_level": 2 },
    { "gender": "female", "skill_level": 1 },
    { "gender": "female", "skill_level": 3 }
  ]
}
```

- 登入者為揪團主；`members` 為**每個座位（含揪團主本人，放第一筆）**，長度必須等於 `party_size`（2～50）。
- 一張訂單佔 `party_size` 個名額，整團放不下 → `409`。
- 成員無帳號，只記性別與程度，會併入統計；**不適用評分系統**。
- 其餘規則同單人報名（重複報名 `409`、時段衝突 `time_conflict`、被拒絕不可再報名、取消後可重新報名，成員會整批被取代）。
- **`current_enrolled` 與名額計算改為加總各訂單的 `party_size`**（單人訂單仍是 1，行為不變）。
- 訂單回應多人報名時多出 `members`。

## 7. 場館停車場

`LocationResponse` 新增 `parking_name`、`parking_latitude`、`parking_longitude`（皆可為 `null`，三者**全有或全無**）。

- 建立/更新可傳這三個欄位，須**一起提供**，否則 `400`。
- 更新時三個都不傳＝不變；要清除請傳 `"remove_parking": true`（不可與停車場欄位同時傳）。

## 8. 程度評分與綜合評級

臨打團結束後，主辦人可選擇性地為個別參加者評定程度；同一使用者在同一球類的所有評分取算術平均，即為綜合評級（類似地圖評價星星）。

| API | 說明 |
|-----|------|
| `PUT /pickup-groups/{id}/ratings/{user_id}` | body `{ "skill_level": 3 }`；評定或改評 |
| `DELETE /pickup-groups/{id}/ratings/{user_id}` | 刪除該筆評分 |
| `GET /pickup-groups/{id}/ratings` | 該團已給出的評分 |
| `GET /users/{id}/skill-ratings` | 某使用者的綜合評級（需登入） |
| `GET /me/skill-ratings` | 我自己的綜合評級 |

綜合評級回應（每個球類一筆，未被評過為空陣列）：

```json
[{ "sport": { "id": "…", "code": "BADMINTON", "name": "Badminton" }, "average": 3.0, "rating_count": 2, "level": 3, "label": "C" }]
```

規則：僅**主辦人或系統管理員**可評；臨打團須已結束（`completed`，或 `active` 且 `end_time` 已過）→ 否則 `409`；被評者須為**已確認**報名者 → 否則 `400`；不可評自己；程度須在該球類對照表內。多人報名的同行成員不適用。

## 9. 站內通知

個人收件匣，僅能看到自己的通知，無推播。事件自動寫入（自己的操作不通知自己）：

| API | 說明 |
|-----|------|
| `GET /notifications?unread_only=&page=&page_size=` | 由新到舊；標準分頁格式 |
| `GET /notifications/unread-count` | `{ "unread": 3 }` |
| `PATCH /notifications/{id}/read` | 標為已讀（冪等，`204`）；非自己的通知 → `404` |
| `POST /notifications/read-all` | 全部標為已讀，回 `{ "updated": n }` |

通知欄位：`id`、`type`、`title`、`content`（繁體中文，可直接顯示）、`pickup_group_id`、`pickup_order_id`（可用於導向）、`is_read`、`created_at`。

`type`：`pickup_order_created`（給主辦人）、`pickup_order_confirmed` / `pickup_order_rejected` / `pickup_order_cancelled_by_host` / `pickup_payment_updated`（給報名者）、`pickup_order_cancelled` / `pickup_order_cancel_requested`（給主辦人）、`pickup_group_cancelled` / `pickup_group_updated`（給已佔名額者）、`skill_rated`（給被評分者）。
