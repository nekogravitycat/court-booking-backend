# 2026-10-07 Frontend Changelog

## 新功能

### 季租 (Booking Series)

- `POST /booking-series`：固定 Resource、固定星期與固定時段，一次建立 3 / 6 / 12 個月的所有預約。
  - body：`resource_id`、`term_months`（3 / 6 / 12）、`start_date`（Location 當地日期）、`weekdays`（0 = 週日 … 6 = 週六）、`start_time` / `end_time`（`HH:MM`，Location 當地時間）。
  - All-or-nothing。與既有預約重疊時回傳 `409`，並列出衝突的 occurrences：

    ```json
    {
      "error": "booking series contains conflicting occurrences",
      "conflicts": [{ "start_time": "2026-11-02T08:00:00+08:00", "end_time": "2026-11-02T09:00:00+08:00" }]
    }
    ```

  - 不受一般預約的「最多 10 筆 upcoming」、90 天提前上限與 Location booking window 限制；但仍須符合營業時間、30 分鐘對齊，且不得已開始或在過去。
  - 建立出的預約狀態皆為 `pending`。
- `GET /booking-series/{id}`：Series 擁有者、組織管理者或 System Admin 可查詢。
- `BookingResponse` 新增 `booking_series_id`（一般預約為 `null`）。

### Location booking window

- Location 新增 `minimum_booking_notice_minutes`（預設 0）與 `maximum_booking_advance_days`（預設 90，上限 90），Create / Update / Response 皆支援。
- 一般預約須滿足 `now + notice <= start_time <= now + advance`；違反時回傳 `400`。
- 兩個 availability API 都不會回傳實際無法預約的時段（含對齊 30 分鐘後的最早時間）。

### Location availability

- `GET /locations/{id}/availability?date=YYYY-MM-DD`：一次回傳 Location 底下所有 Resources 的可預約時段，依 Resource 分組。與 `GET /resources/{id}/availability` 共用同一套計算。

### 批次建立臨打團 (Pickup Group Series)

- `POST /pickup-group-series`：前端把 recurrence 展開成 `occurrences`（每筆 `start_time` / `end_time`），後端每筆建立一個獨立的臨打團，並共用 `pickup_group_series_id`。
  - 共用欄位與單團相同，另需 `registration_deadline_minutes_before_start`（每場截止時間 = 開始時間 − 此分鐘數）。
  - 最多 64 場；每場開始時間不得在過去、不得超過現在起 90 天；任一場驗證失敗則整批不建立（`400`）。
- `PickupGroupResponse` 新增 `pickup_group_series_id`。

### 臨打團 `social`

- 新增 `social`（最多 500 字的任意文字）。Create / PATCH / Response 皆支援。
- PATCH：省略 = 不修改、字串 = 設定、`null` = 清除；純空白視為 `null`。

### 缺席標記與統計

- `PUT /pickup-groups/{id}/orders/{order_id}/absence`：團主或 System Admin 將 `confirmed` 訂單標記為缺席。須在團結束後（`now >= end_time`）、團未取消；否則 `409`。
- `DELETE /pickup-groups/{id}/orders/{order_id}/absence`：撤銷缺席標記（`204`）。
- `PickupOrderResponse` 新增 `attendance_status`（`null` / `absent`）、`attendance_marked_by`、`attendance_marked_at`。
- `GET /users/{id}/pickup-stats`（登入即可）：回傳 `pickup_participation_count`、`pickup_absence_count`、`pickup_absence_rate`。沒有參加紀錄時 `pickup_absence_rate` 為 `null`（不是 0）。
