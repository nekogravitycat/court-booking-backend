# 2026-10-01：帳號自評程度、創團權限、API 修正與新增欄位

## 帳號自評程度

- `GET /me/skill-levels`：以 `{items, page, page_size, total}` 單頁回傳所有已設定運動。
- `GET /me/skill-levels/{sport_id}`：讀取指定運動；尚未設定回傳 400。
- `PUT /me/skill-levels/{sport_id}`：body `{ "skill_level": 2 }`，建立或取代自己的設定。
- `DELETE /me/skill-levels/{sport_id}`：清除設定，冪等回傳 204。

每個帳號、每個運動各有一筆設定，可只設定自己有參與的運動。
程度須為該運動已定義且啟用的 1–100 整數，運動本身亦須啟用。
自評程度與 `/me/skill-ratings` 的主辦人評分獨立。

## 報名 API

`POST /pickup-groups/{id}/orders` 不需 body。伺服器讀取帳號中該團運動的設定，
保存為訂單的 `skill_level` 快照。舊客戶端傳入的 `skill_level` 會被忽略；
不能用報名 body 繞過帳號設定。尚未設定或運動/程度停用時回傳 400。

多人報名仍以 `members[0]` 表示本人，這筆 `skill_level` 可省略並由帳號設定覆蓋。
匿名同行者仍必須提供程度。所有成員程度均保存在訂單中。

選用快照的原因：修改帳號程度不應改變發起人先前審核的依據或既有程度統計。
取消後重新報名會重新取得當下的帳號程度。既有訂單保留原值；
不從舊訂單回填帳號設定，使用者須明確設定自己的程度。
快照保存程度整數，顯示標籤仍使用運動對照表。

## 創團權限

所有已登入且啟用的使用者都能建立臨打團，`host_id` 固定取自 Token。
創建者可編輯自己的團、審核報名及使用既有團主功能，無需 `is_pickup_host`。
不會自動授予 pickup host 角色；該角色仍用於既有教練清單與追蹤功能。
系統管理員仍能編輯任意團；刪除團的權限維持系統管理員限定。

新增 migration 000009，啟動時自動建立 `user_skill_levels`；不更動既有 migration。

## API 權限與行為修正

### 臨打團與報名訂單

- **權限收緊**：`GET /pickup-groups/{id}/orders` 與 `GET /pickup-groups/{id}?include_orders=true`，僅團主本人或系統管理員可用，其他使用者回傳 403。
- 單人／多人報名與恢復已取消的訂單會重新檢查團狀態、名額及時段衝突；停用、已取消、已完成或已結束的團不能報名（400）。名額不足、重複報名或時段衝突回傳 409。已取消的團不再阻擋其他重疊時段的報名。
- `PATCH /pickup-groups/{id}`：已有任何報名或評分紀錄後，不可修改 `sport_id`（409）。縮減容量、修改時段及重新啟用會原子檢查；容量低於已報名人數或參加者與其他團時段衝突時回傳 409，整筆修改不生效。
- `PATCH /pickup-orders/{id}`：報名者對已確認、已付款或已申請取消的訂單，不能自行設為 `cancelled`（403）；須使用 `cancel_request`，由團主或系統管理員核准。
- `DELETE /pickup-groups/{id}`：已有訂單或評分紀錄時回傳 409。

### 組織、場館、資源與預約

- 組織停用後，非系統管理員對組織、場館、資源及其封面／成員／管理員的相關異動，以及新增、修改或刪除預約，回傳 403；歷史資料仍可讀取。
- 組織擁有權轉移與角色指派改為原子操作。指派組織管理員或場館管理員時會檢查互斥角色，衝突回傳 409；指派組織管理員的對象尚非組織成員時回傳 400。
- 組織管理員修改自己的預約時，亦適用管理員權限。
- 刪除仍有相關預約的資源或其場館時回傳 409；刪除失敗會保留封面。

### 個人資料與清單回應

- 更新個人資料、頭像或組織封面時，不再覆蓋並行修改的啟用狀態／管理員旗標。
- 使用者清單 `sort_by=name` 正確依 `display_name` 排序，同值以 ID 穩定排序。
- 清單查詢超出最後一頁時，`items` 為空但 `total` 仍回傳符合篩選的實際總數；讀取資料失敗會回傳錯誤，不再回傳不完整的成功清單。

## 系統管理員手動發送站內通知

對應 commit `ba5d53d249279a5e8012a542fe06d9e200d04bda`。

新增 `POST /notifications`，僅已登入且啟用的系統管理員可用：

```json
{
  "user_ids": ["使用者 UUID"],
  "title": "通知標題",
  "content": "通知內容"
}
```

- `user_ids`：1–100 位不重複的有效使用者，全部成功或全部失敗。
- `title`：去除前後空白後 1–100 字；`content`：去除前後空白後 1–2000 字。內容為純文字，前端應以文字方式呈現。
- 成功回傳 201，body 為 `{ "sent": 1 }`（實際發送人數）。無效內容、重複 UUID 或收件者不存在／停用回傳 400；未登入回傳 401；非有效系統管理員回傳 403。
- 每位管理員每分鐘最多 10 次成功發送，超過回傳 429。
- 通知清單的 `type` 新增 `admin_message`，前端需支援此通知類型。

## 臨打團報名截止時間 — Breaking

對應 commit `ba5d53d249279a5e8012a542fe06d9e200d04bda`。

- `POST /pickup-groups` **新增必填** `registration_deadline`，使用 RFC 3339 日期時間（例如 `2026-10-02T18:00:00+08:00`）；舊客戶端須補上此欄位。
- `PATCH /pickup-groups/{id}` 可選填 `registration_deadline`；省略保留原值。
- 截止時間不得晚於 `start_time`。建立、修改截止時間或修改開始時間時，截止時間不得為過去時間，違反回傳 400。
- 團列表、團詳細資料及訂單內的團摘要新增 `registration_deadline`。
- 到達截止時間後，單人／多人報名及恢復已取消的訂單回傳 400。此限制取代前一個 commit 允許開始後、結束前仍可報名的行為。
- 既有團的截止時間由 migration 回填為 `start_time`。

## 使用者 LINE ID

對應 commit `ba5d53d249279a5e8012a542fe06d9e200d04bda`。

- `POST /auth/register`、`PATCH /me`、`PATCH /users/{id}` 新增選填 `line_id`。
- 非空值須為 4–20 個小寫英數字或 `.`、`-`、`_`（`^[a-z0-9._-]{4,20}$`），格式不符回傳 400。
- PATCH 傳 `"line_id": ""` 可清除；省略或傳 `null` 保留原值。註冊傳空字串視為未設定。
- 使用者回應新增可為 `null` 的 `line_id`，僅本人與系統管理員可見。

新增 migration `000010`，啟動時自動加入 LINE ID、報名截止時間與手動通知發送紀錄。
